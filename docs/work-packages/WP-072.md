# WP-072 - Incorporar gobernanza de actualización del manual de ayuda

## Estado documental

`APROBADO`

## Objetivo

Convertir en regla permanente que todo cambio del sistema evalúe explícitamente si requiere actualizar el manual HTML para usuario o soporte técnico, y que la actualización se realice en el mismo trabajo cuando corresponda.

## Resultado esperado

La gobernanza canónica y el template de Work Packages obligan a evaluar impacto sobre `manual/index.html`. Ningún cambio relevante para operación, usuario o soporte puede integrarse dejando el manual desactualizado silenciosamente.

## Dependencias

- WP-067 `INTEGRADO`: manual HTML canónico existente.

## Fuentes canónicas obligatorias

- `AGENTS.md`.
- `docs/14-gobernanza-agentes.md`.
- `docs/work-packages/TEMPLATE.md`.
- `docs/implementation/ORQUESTACION.md`.
- `manual/index.html`.
- DEC-005 y DEC-019.

## Decisión humana cerrada

Cada vez que se modifique algo del sistema debe evaluarse si el cambio necesita ser explicado al usuario o al soporte técnico.

- Si **sí**, `manual/index.html` debe actualizarse dentro del mismo WP/PR o cambio autorizado.
- Si **no**, la entrega debe registrar explícitamente que el impacto sobre el manual fue evaluado y no requiere actualización.
- La regla aplica tanto a nuevas funciones como a cambios de comportamiento, operación, configuración, instalación, diagnóstico, textos relevantes o flujos de soporte.
- No se exige documentar en el manual detalles internos de desarrollo sin utilidad para usuario/soporte.

## Alcance

- Incorporar la regla en la gobernanza canónica más visible para agentes.
- Incorporar una verificación obligatoria en `docs/work-packages/TEMPLATE.md`.
- Ajustar `docs/implementation/ORQUESTACION.md` si hace falta para que ORCHESTRATOR/IMPLEMENTER/REVIEWER verifiquen el punto en planificación, entrega y revisión.
- Mantener compatibilidad con DEC-005: cambios puramente documentales autorizados pueden seguir el mecanismo previsto allí.
- Mantener compatibilidad con DEC-019: la regla de documentación no altera qué eventos ejecutan CI.

## Fuera de alcance

- Reescribir el contenido completo del manual.
- Cambiar funcionalidad de producto.
- Crear automatización que decida semánticamente por sí sola si el manual necesita cambios.
- Convertir todo cambio técnico interno en contenido para usuario.

## Componentes previsiblemente afectados

- `AGENTS.md`.
- `docs/14-gobernanza-agentes.md`.
- `docs/work-packages/TEMPLATE.md`.
- `docs/implementation/ORQUESTACION.md` si corresponde.

## Criterios de aceptación

1. Existe una regla canónica inequívoca de evaluación de impacto sobre el manual.
2. El template de WP exige indicar la documentación de usuario/soporte afectada o declarar que no aplica.
3. La checklist de entrega exige verificar el manual antes de cerrar.
4. La regla distingue contenido útil para usuario/soporte de detalles internos de desarrollo.
5. REVIEWER puede verificar objetivamente que el impacto fue considerado.
6. No se contradicen DEC-005 ni DEC-019.
7. El formato parseable de los WPs permanece válido.

## Pruebas obligatorias

- Revisión de consistencia documental.
- Validación del formato parseable del template/documentos por los tests/scripts existentes que correspondan.
- `git diff --check`.
- CI completa de la PR, por tratarse de una Pull Request aunque sea documental.

## Invariantes y restricciones

- No rebase.
- No force-push.
- Squash merge.
- Revisión independiente obligatoria.
- No modificar código ejecutable.
- No cambiar la política de CI de DEC-019.
- No debilitar el rol de HUMAN_GATE.
- WP-029 permanece BLOQUEADO.

## Documentación a actualizar

Los propios documentos de gobernanza enumerados en el alcance.

## Hallazgos fuera de alcance

Registrar cualquier propuesta de automatización futura por separado.
